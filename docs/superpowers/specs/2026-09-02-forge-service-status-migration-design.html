摘要

ABACUS-Forge 是 Paimon v1.3 的协议无关 ABACUS 单元操作基座，也是面向人类研发者和 AI Agent（Codex、OpenCode，以及作为 ADAM-ABACUS 的 Paimon）的快捷消费面。它以单工作目录、版本化 contracts、稳定 Python API 和 Agent-first CLI 提供输入准备、执行、结果收集、后处理与导出；不是调度平台、厚 workflow 或科学判断层。

本 SPEC 整合当前已确认的产品定位、消费模式、职责边界与 Service/Status 迁移决策。它在 2026-09-01 契约优先设计之上细化下一阶段的公共行为；保留已验证的解析、结构处理和旧 API/CLI 兼容层，不进行一次性重写。

职责结论：Forge 只返回执行事实、解析观察、产物和收集完整性。科学验证与接受判断、任务编排、重试/续算以及平台和调度选择全部上移到人类/Agent；Forge 不生成 accepted、guarded 或 rejected 等科学结论。

默认输入策略：ABACUS prepare profile 的 dft_functional 默认值显式为 pbe；调用方仍可通过 typed request 或参数覆盖。该默认是输入生成策略，不是科学验证或接受结论。

产品定位与消费模式

Forge 的“快捷消费”指在明确 workspace 与显式请求下，快速获得可审计的 ABACUS/PyATB 执行事实、解析观察和可复用 artifact；不是用菜单、数字 Task-ID 或隐式目录状态替代协议。

交互不变量：无论调用者是谁，operation、typed request、workspace、operation_id、artifact、状态、错误类别与退出语义均相同。核心 operation CLI 默认在 stdout 输出单个 JSON envelope，诊断写 stderr；--format=text/--pretty 只是人类渲染。现有 legacy CLI 可暂留 --json 兼容开关，但它不是“Agent 模式”，也不得改变执行行为。核心 service 与机器 CLI 不依赖 prompt 或 TTY 自动换协议；TUI 可以拥有 prompt/TTY，但只负责收集参数、调用同一 API/结构化 CLI 并渲染结果。

目标与非目标

目标

  • 提供同等稳定、同一语义的 Python API 与 Agent-first CLI；两者共同消费 typed request/result 和 operation service。
  • 提供具名单元 operation 的 capability/task pack 作为快捷消费层，声明成熟度、输入/输出 artifact、engine 与可选依赖；pack 不在 Forge 内串联多 operation。
  • 为 prepare、modify、execute、collect、postprocess、export 建立可审计事件，并返回原始观察和收集完整性。
  • 把 runner、engine、collector、postprocessor 与 service 拆开，保留已验证的输入/解析实现。
  • 让 UnitSpec、旧 result dict、旧文件和旧 CLI 只承担兼容映射，不让新 service 依赖 God Object。
  • 为 Paimon thin adapter、Codex/OpenCode 调用和未来 TUI 提供稳定、无平台语义的 facts envelope。

非目标

  • 本阶段不实现 ATP/MCP、AsterFire Tool、tool_data、task_id、AiiDA、Slurm、Bohrium、DPDispatcher、数据库或恢复型 workflow。
  • 不进行科学解释、研究建议、任务编排、重试/续算、平台调度或用户决策；Forge 只交付执行/收集事实与解析观察。
  • 不让 TUI、prompt、TTY 判断、数字 Task-ID 或目录命名成为能力协议；允许 TUI 作为 API/CLI 之上的交互适配器，但不承载执行/收集语义、科学判断或独立状态机。
  • 复用已有 ABACUS 输入、结构、日志和 PyATB 实现；对已复现的格式、单位、数据丢失和解析完整性缺陷作有回归证据的修复。
  • 本阶段不把 property pack、复杂 MD 或 PyATB 的科学判定写入 Forge；它们只提供已实现的单元操作和解析产物。
  • 本阶段不移除旧 public API、旧 CLI 或兼容文件。

状态语义与事实观察

Forge v1 只定义执行与收集状态：execution ∈ {not_run, completed, failed, skipped}，collection ∈ {not_collected, complete, partial, missing_output}。normal_end、convergence、parser_complete、数值指标和日志片段都是带来源的 observations/checks，不是科学接受状态。科学验证、任务编排和平台调度由上层人类/Agent 决定。

事实映射规则

  • execution：进程正常结束且返回码为零为 completed；非零退出、超时、缺 executable、信号终止或 runner 异常为 failed；显式 dry-run 或显式跳过为 skipped。normal_end 是独立 observation，不得被隐式吞并。其中「缺 executable」若在进程启动前发现（尚无任何执行事实），按设计决策中的失败类别映射表返回 error envelope；failed 只描述进程确已启动后的结果 envelope。
  • collection：所有 requested artifacts 存在且解析完成为 complete；部分结果或解析降级为 partial；关键输出不存在为 missing_output；尚未收集为 not_collected。
  • SCF collect：所需数据为 workspace 内的非空输出日志与可解析的有限总能量；没有日志为 missing_output，缺能量、解析错误或来源选择歧义为 partial，数据齐全为 complete。收敛标志只作观察，缺少可选 time/report JSON 不影响完整性。审计 manifest、events、claims 和锁不作为领域输出 artifact，路径别名遵循同一规则。
  • 旧字段 normal_end、converge、relax_converge 只作为兼容输入和 observations 来源；任何接受、拒绝或科学解释都由上层产生。

兼容边界：当前 contract foundation 中的泛型 ForgeRequest 仍只接受五个核心 operation（prepare、modify、execute、collect、export），本阶段不得静默扩大其旧构造器语义。postprocess 是新 service 层的独立 typed request 与事件 operation；其 request registry、序列化形态和兼容映射必须在实现 PLAN 中明确，不能把它偷偷塞回旧 ForgeRequest 或把旧 collect 事件改写成后处理事件。

设计决策与替代方案

冻结契约：operation identity、admission、event 与 artifact reference。每个 v1 request 必须携带标准小写 UUIDv4 operation_id；稳定 Python API 的便利构造器可生成它，但进入 service 的 typed request 不得缺失。调用方若重复执行，显式创建新的 operation ID；service 不以 ID 返回旧结果，也不以 ID 实现工作流恢复。完成纯 request/schema/path 校验后，service 必须在任何 workspace 领域写入、兼容文件写入或 runner 启动前，以原子 exclusive create 写入 admission record；已有同 ID admission 或 event 均抛 operation.conflict。admission 由不可猜测的 owner token 持有，只有该 token 能提交对应 event；PID 存活检查不是所有权证明。

崩溃与持久化边界：admission 是“该 ID 已被受理”的持久 tombstone，不是可租约、缓存或幂等结果。成功 event 完整落盘并进入 manifest 后可由 owner 删除 admission；任何异常、进程崩溃或 event/manifest 持久化失败都保留 admission，不得按 PID、时间或文件年龄自动回收。后续调用必须使用新 ID；显式维护工具如未来需要，另行设计，不进入 service 自动路径。Forge 不承诺回滚任意领域文件，但保留 admission 以阻止同 ID 静默重放，并以 class 5 报告持久化失败。

单 workspace 一致性：v1 service 在 admission、领域副作用与 event commit 外层持有 workspace operation lock；不同 operation ID 也不得并发修改同一 workspace。该锁只保护本地文件与审计一致性，不负责跨 workspace 编排、排队、资源调度或恢复。

workspace event 的 id 等于 request ID；已存在的 v1 旧 event 保持历史兼容，新 event 不再生成第二个关联 ID。artifact 的 id 只在生产 result 内唯一；跨 operation 输入使用 {operation_id, artifact_id} 引用，不允许绝对路径或隐式“最近一次结果”。

边界：artifact 必须位于其 workspace root 内。外部已执行目录可被作为 collect request 的 workspace root 显式收集；跨 workspace 消费须在 prepare 中以显式 source reference materialize/link 并记录 provenance，不允许 collect/postprocess 偷读外部路径。这保留单 workspace 原子性，而不把 DAG 变成 Forge 核心协议。

冻结契约：outcome/error envelope 与 exit class。service 成功受理并交付事实时返回 OperationOutcome（forge.operation-outcome/v1），其中包含 operation_id、不变的 ForgeResultEnvelope（forge.result/v1）和 typed observations；预期的请求、前置条件或 Forge 自身失败返回 ForgeErrorEnvelope（forge.error/v1）。error envelope 必有 error.class、message、affected_fields 与 operation_id；只有 request 尚不能解析出它或 workspace 时，相应字段才可为 null。v1 机器路径 CLI 默认在 stdout 输出其中恰一个 JSON 文档：0 表示 service 已交付执行/收集事实，2 表示 request/schema/path/conflict，3 表示 environment/precondition，4 表示受控外部进程已启动但失败，5 表示 Forge internal/persistence failure。stderr 仅含诊断，API 不通过 subprocess 重走 CLI。

稳定错误类：error.class 只取 request.invalid、request.schema、request.path、operation.conflict、precondition.missing、persistence.failure、internal.failure。实现以类型化内部异常映射，不解析异常 message。可识别的 executable/输入资产缺失属于 precondition；runner 在尚不能证明进程启动时抛出的其他意外异常属于 internal；进程已启动后的非零、超时、信号或 runner 失败进入 outcome 的 execution facts。

排除：以异常文本、returncode 原样透传或 stdout 人类文本让 Agent 推断失败类别；这些做法无法形成跨语言稳定协议。

失败类别 → envelope × exit class 映射（2026-09-03 审查修订冻结）：判据是受控外部进程是否已启动并产生执行事实——已启动则交付结果 envelope（即使 execution=failed），未启动则交付 error envelope。

结果关联与兼容：ForgeResultEnvelope 不新增 operation_id 或 observations 字段，其序列化 key set 保持冻结；新 Python API 与 v1 机器 CLI 由外层 OperationOutcome 同时携带 ID、result 与 observations，持久化 event 的 id 仍等于该 ID。error envelope 自描述并携带 operation_id。legacy CLI/API 继续直接使用旧 result，不被静默包裹。

冻结契约：双 CLI 面而非静默改写 legacy。新增 abacus-forge operation <prepare|modify|execute|collect|postprocess|export> --request FILE 与 --stdin（二者互斥），以及 schema/capabilities discovery；该 v1 命令面默认 JSON，--format=text/--pretty 只渲染同一 envelope。既有 prepare、modify、execute、collect、task pack 与 --json 是 legacy surface，默认输出、参数和行为不变，直到另行版本化废弃。新稳定 Python API 直接暴露同一 typed service；旧 UnitSpec/result API 仅向新 service 做适配。

决策 1：状态只记录执行/收集事实。服务返回执行状态、收集状态、observations/checks、metrics 与 artifact refs；不维护科学 policy registry，不接受 policy_id，也不在 OperationStatus 中推导科学结论。observations 以 typed Observation 记录（name/value/source，source ∈ log/file/parser/runtime），由 OperationOutcome 在 Python API、v1 机器 CLI 与 operation event payload 中同形交付；它不进入内嵌 forge.result/v1 的冻结 key set。

旧 scientific 字段：该字段仅是 deprecated compatibility input/output。反序列化旧记录可接受历史四值；所有新 Forge service、result factory 与兼容投影一律写 unassessed，不得据 observations/checks 推导其他值，也不得引入 policy_id 或 policy registry。未来 major schema 可删除该字段。

决策 2：normal_end 是 observation，不是结论。returncode、termination、normal_end、convergence 和 requested artifacts 分别保留。上层可据此决定是否接受结果或继续操作。

排除：沿用当前 `_looks_completed()` 以任意 “SCF CONVERGED/TOTAL TIME/NORMAL END” 统一跳过后续执行；它把日志观察误当成执行控制。

决策 3：engine/collector 观察、service 交付。ABACUS/PyATB adapter 只提供 command、原始日志、退出事实、领域输出和 artifact；service 负责输入、路径、执行和收集完整性，并把观察原样交给上层，不负责科学解释。

排除：把 task、plot、workflow、scheduler 或平台资源策略塞进 LocalRunner/engine。

决策 4：兼容 shim 优先。旧 UnitSpec 仍可调用，新增 typed request 先映射到既有 prepare/modify/execute/collect 实现，再逐步收敛内部模块。旧文件和旧 API 的废弃必须另有版本窗口。

排除：一次性重写全部 task pack；这会同时改变物理行为、文件布局和迁移归因。

决策 5：双稳定面、同一 service。稳定 Python API 直接调用 operation service；CLI 只解析 request、调用同一 service 并渲染 envelope；Paimon Tool 与未来 TUI 复用 API/service 或结构化 envelope，不能复制业务逻辑。TUI 可以提供 VASPKIT/AbacusCopilot 风格的菜单、提示、参数预览和结果展示。

排除：让 Python API 与 CLI 分别实现 prepare/execute/collect，或让 TUI 解析人类 CLI 文本、维护第二套状态机或执行语义。

决策 6：JSON 是传输编码，不是 Agent 身份。核心 CLI 的 JSON stdout 用于稳定跨语言消费；人类文本是同一 envelope 的渲染。Forge service 与机器 CLI 不得根据调用者、TTY 或 --json 走不同执行/状态分支；TUI 的交互分支只存在于壳层，不改变 service 语义。

排除：用 --json 切换“Agent 模式”，或自动检测终端后悄然改变协议。

决策 7：operation_id 用于调用关联与一次性受理冲突检测。每次 service invocation 使用 request 中的 UUIDv4 operation_id（便利构造器可生成），admission、事件和 artifact 以它关联；重复 ID 被拒绝，但 Forge 不按 ID 返回旧结果，也不提供幂等结果、恢复、重试或工作流语义。task name 仅作 convenience metadata，外部 job/task id 只能进入上层 adapter metadata。

排除：要求 Agent 先列出菜单、选择数字任务或依赖目录 slug 才能调用能力。

决策 8：不再以日志片段静默跳过执行。当前 legacy run_many(skip_completed=True) 的 “SCF CONVERGED / TOTAL TIME / NORMAL END” 推断不能进入 v1 runner/service。v1 的 dry-run 或显式 skip 必须由 request 声明并写为 execution=skipped；需要复用已有运行结果时，上层提交 collect request，而不是让 runner 猜测。

组件职责

  • contracts：版本、字段类型、JSON-safe、路径、artifact、错误和 capability descriptor；不包含开放式科学解释。
  • public API：稳定 Python 入口，直接调用 service 并返回 typed envelope；不通过 subprocess 回调 CLI。
  • CLI：request 解码、service 调用、JSON/text renderer 与 exit mapping；不得携带第二套 operation 逻辑。
  • services：接收 typed request，调用 core/engine/runner/collector，产生 execution/collection envelope 和事件。
  • core：INPUT/STRU/KPT、结构和资产归一化；保留 STRU 的赝势/轨道引用、质量、已有共线磁矩与移动标志，显式覆盖只改变指定项；写出原生 Bohr 晶格单位，未支持的坐标模式明确拒绝。周期真空识别按周期间隙和晶胞几何处理。不依赖 runner、平台或 scheduler。
  • runner：只执行明确 command，返回 returncode、termination、timeout、stdout/stderr 和 runtime diagnostics。
  • engine adapter：ABACUS/PyATB 特定 command、输入检查和原始输出；可选的 atst-tools 适配器只委托 NEB 图像/链路编排及并行执行语义的 prepare/execute/postprocess，并返回原始事实，不决定上层 workflow 状态、站点启动或 Slurm 调度。ATST 使用的后端和模型（包括 DeePMD）由 atst-tools 与调用方的配置负责，Forge 将其视为不透明配置，不选择、安装、配置或进行科学评估。
  • collector/postprocessor：从 artifact 提取 normal_end、convergence、指标和 parser observations；不把观察转换为科学接受状态。
  • packs：以具名 capability 暴露 SCF、relax、band、DOS、PyATB、property 以及可选的 atst-tools NEB 入口；每项声明 maturity、supported operations、artifact、engine 和可选依赖。
  • compat：把 UnitSpec、旧 result 对象和旧文件投影到新 service；新代码不得反向依赖旧 God Object。

最小接口形态

实现计划必须把下列逻辑接口固化为 Python protocol 或等价的窄接口；具体 dataclass 字段以执行计划为准，但不得重新引入宽泛 UnitSpec：

PrepareService.prepare(PrepareRequest) -> OperationOutcome | ForgeErrorEnvelope
ModifyService.modify(ModifyRequest) -> OperationOutcome | ForgeErrorEnvelope
ExecuteService.execute(ExecuteRequest) -> OperationOutcome | ForgeErrorEnvelope
CollectService.collect(CollectRequest) -> OperationOutcome | ForgeErrorEnvelope
PostprocessService.postprocess(PostprocessRequest) -> OperationOutcome | ForgeErrorEnvelope
ExportService.export(ExportRequest) -> OperationOutcome | ForgeErrorEnvelope

Stage 3 已交付按 operation 的 protocol 与 ScfServiceSet；ForgeServices 仅保留为旧调用方的委托 shim。后续 capability 沿用窄 service 接口和共用的 workspace/event 机制。

所有 service 都使用同一 Workspace、ArtifactRecord、OperationStatus 和 event persistence；跨 workspace 的 DAG、资源选择、重试编排由上层实现。

PostprocessRequest 是对后处理程序或纯解析器的显式描述，允许它拥有自己的 operation_id 与输入 artifact refs；它不改变上游 ABACUS execute/collect 的状态，也不赋予 Forge 编排、调度或报告职责。可选 atst-tools adapter 承接外部 atst neb post 时，映射为 Forge 的 postprocess operation，不新增顶层 post 动词。当前泛型 ForgeRequest 的五动词兼容集合不被静默扩大；新 PostprocessRequest 由独立 typed request registry 与 compat mapping 引入。

错误处理

类别Forge 行为调用方后续动作
admission 前 request/schema/path 错误返回 class 2 request error；不写 event，不启动 runner，不产生领域副作用。调用方修正 typed request 后，以新 operation_id 重试。
admission 后 prepare/modify 输入资产或环境前置失败返回 class 3 precondition.missing；保留 admission 与受影响字段，不写成功 outcome。修正输入/环境后以新 operation_id 调用。
缺 executable（进程启动前发现）返回 class 3 precondition.missing；不启动 runner、不写执行事实，保留 admission。调用方修复环境后以新 operation_id 重试。
timeout / 非零退出 / 信号终止（进程已启动）写入 stdout/stderr artifact 和 execution failed event；collection 保持 not_collected。调用方修复环境后决定重复执行或新建 operation，不覆盖旧 event。
returncode=0 但 normal_end 缺失/失败execution 可为 completed；保留 normal_end observation，collect 可为 partial。调用方检查日志和 requested artifacts，再决定是否重新 collect。
收敛观察为否或缺失保留 convergence observation 与可用 artifact，不产生科学接受状态。由人类/Agent 决定修改输入、重复执行、续算或接受。
输出缺失/解析不完整collection partial 或 missing_output；diagnostics 指向缺失 artifact 和 parser。补齐输出、选择正确 parser 或重新 collect。
外部 postprocessor 失败只标记 postprocess operation 的 execution failed；不得回写上游 ABACUS execution。修复本地程序或输入后重试 postprocess。
event/manifest 持久化失败返回 class 5 persistence.failure 并保留 admission；即使进程已经失败，该错误也优先于原本的 process outcome。不得以同一 ID 自动重放；检查诊断后使用新 ID。
其他 Forge 内部异常返回 class 5 internal.failure；若已 admission 则保留 tombstone。检查实现/诊断后使用新 ID。

ForgeErrorEnvelope 保留 error class、operation_id、workspace reference、受影响字段和人类可读 message；OperationOutcome 保留 operation_id、workspace result、artifact/check refs 与 observations。v1 机器 CLI 默认 stdout 是单个 outcome/error JSON 文档，stderr 只承载诊断；文本 renderer 复用该对象，不重新解释状态。

测试与门禁

  • contract：每一种 typed request、capability descriptor、status、OperationOutcome/error envelope 的 round-trip；UUIDv4 operation_id/admission/event identity、未知字段、路径 containment、JSON-safe、跨 operation artifact ref 与外部路径拒绝。
  • API/CLI parity：同一 request 经稳定 Python API 与 CLI 产生等价的 envelope、状态、checks 和 artifact refs；CLI 不能拥有独立业务实现。
  • CLI process：v1 机器路径 operation CLI 的 stdout 恰含一个 JSON outcome/error 文档，stderr 是诊断；分别断言 0/2/3/4/5 exit class；无隐式 prompt、无 TTY 协议分支、text/pretty renderer 只改变显示。legacy command 的默认 stdout 与 --json 回归独立保持。
  • operation/observation matrix：逐项覆盖 prepare、modify、execute、collect、postprocess、export、dry-run、缺 executable、timeout、非零退出、signal termination、normal_end 缺失、收敛观察、缺输出和 parser partial；execute 的零退出、非零、timeout 与 signal 至少由真实 LocalRunner 子进程测试验证，不以手工构造 diagnostics 替代；不测试 Forge 的科学接受判断。
  • protocol：fake runner/engine/collector 验证 service 只消费窄接口；engine、TUI adapter 与 Tool adapter 不得把 ATP/MCP、AiiDA、scheduler、平台或旧运行时包泄漏进 Forge core。TUI adapter 只能调用 API 或结构化 CLI envelope。
  • compat：现有 tests/test_contracts.py、tests/test_workspace.py、tests/test_result_contract.py、tests/test_units.py 与 CLI/API 回归保持通过；旧 to_dict()、文件字节和目录布局不变。
  • artifact/event：调用追加、跨操作引用、词法路径与 symlink resolved target 的 workspace containment、外部 artifact 拒绝、失败保留日志、同 workspace operation serialization、并发同 ID 拒绝、崩溃 admission 不回收、owner token 校验，以及 event/manifest 失败后不重放副作用。
  • offline gate：默认测试不访问真实集群；benchmark 和 real_smoke 仍需显式启用。它们只证明操作、解析和兼容性，不替代人类/Agent 的科学判断。

迁移与发布

2026-09-09 收口：Stage 3 已合并至 a800b64，Stage 4 首批 relax/cell-relax 与可选 atst-tools NEB adapter 已按独立 PLAN 合入 main（ee471b6）；当前这些能力均保持 experimental，稳定发布仍需各自的 compat、benchmark、clean-environment 与 real-smoke 证据。后续批次仍包括 MD、独立 postprocess/export 与 PyATB；各批次继续独立提供 PLAN 和验证证据。

  1. Stage 0 — Contract freeze：本 SPEC 已批准；锁定 operation admission/event/artifact refs、outcome/error envelope 与 exit class、公共 API/CLI 双稳定面、execution/collection 状态、JSON stdout 与旧兼容边界。
  2. Stage 1 — Request/API：新增 per-operation request、UUIDv4 event mapping、artifact-ref validator 与稳定 Python API；不改变旧 API/CLI，补齐 operation/observation matrix 和 API contract tests。
  3. Stage 2 — SCF vertical slice：以 SCF prepare → modify → execute → collect 贯通 service、ABACUS engine、runner、collector、workspace event 与 API；移除 v1 对日志片段的静默 skip，确认旧输出兼容。
  4. Stage 3 — Agent-first CLI：加入 request-file/stdin、capability/schema discovery、默认 JSON stdout/error envelope、exit class 与 process parity tests；legacy CLI 维持兼容。
  5. Stage 4 — Relax/MD/postprocess/PyATB/optional ATST NEB：按真实证据迁移单元操作和解析能力；可选 atst-tools NEB 适配器只复用 Forge 的 prepare/execute/postprocess operation，并把图像/链路编排及并行执行委托给 atst-tools；各 capability 只声明自己实际支持的输入、命令和产物，Slurm 与站点调度保持在 Forge 外。
  6. Stage 5 — Adapter/UX/上层验收：在新的独立 paimon-v3 仓实现 Paimon thin adapter；TUI 在稳定 API/CLI 之后按需实现；由上层完成科学判断、编排与平台适配，并完成 compat、benchmark、real_smoke 与 shim hardening。

每个 Stage 都是独立可审查的计划和提交。Stage 2 之前不得将 Paimon v1.2 切换为新后端；任何能力只有在 compat、benchmark 和 real_smoke 证据满足后才进入 Paimon v1.3 稳定面。paimon-v3 是独立于 Forge 的 Agent/adapter/benchmark 发布源；当前 app-tools/toolbox/ABACUS 继续维护 v1.2，并只在受控部署时消费 v3 产物，不复制 Forge 或 Paimon 核心逻辑。已结项 paimon/ 保持历史证据库，不作为 v1.3 开发基线。TUI 不是 v1.3 后端切换门槛。

回滚策略是保留旧 shim 和事件记录：若新 service 或 engine adapter 失败，上层可回退到旧 API；不得删除已经写入的 workspace event 或覆盖旧兼容文件。

Stage 4 首批：relax / cell-relax

新增四种 Relax typed request，均显式携带 capability=relax|cell-relax，对应 prepare、modify、execute、collect；operation CLI 语法保持不变。既有 SCF 请求的字段与序列化保持兼容；CLI 中不含 capability 的请求仍按 SCF 解码。未知 capability 返回 request.invalid/2，已知 capability 的字段错误返回 request.schema/2。每项发现记录仅声明实际实现的操作，成熟度保持 experimental。

prepare 使用相应 ABACUS calculation profile；与 capability 冲突的 calculation 参数作为请求错误拒绝，modify 不得删除或改为其他 calculation。execute 对已有 INPUT 的 calculation 做前置一致性检查；collect 允许收集外部准备的目录，只依据显式请求和输入文件检查能力匹配，不要求先有 Forge prepare 事件。它们复用窄 service、runner、解析器与 workspace 事件机制，不串联操作。

relax collect 将总能量、力、应力、relax 步数、最终结构及已有收敛观察如实交付；缺失的观察不得伪造为否。收集完整性按日志、可解析能量与最终结构判定：没有输出日志为 missing_output；缺能量、最终结构不可解析或 parser 降级为 partial；所需数据齐全为 complete。收敛真值和 ABACUS 返回码不参与科学接受判断，也不替代收集完整性。最终结构通过 workspace-relative artifact 引用交付，数组和结构快照可进入外层 Observation，内嵌 result key set 不变。

风险与开放项

风险 1：旧 UnitSpec 覆盖面很宽。迁移可能暴露隐式字段依赖。缓解：先 SCF 纵向切片，shim 保持旧字段，compat fixtures 记录每个映射。

风险 2：MD、复杂 PyATB 和 property pack 的输出形态各异。缓解：按 capability 记录 execution/collection 事实、解析观察和 artifact，不把单一返回码或 convergence 标志扩展成结论。

风险 3：normal_end 日志可能截断或被多 rank 输出分散。缓解：normal_end 作为有来源的 check，要求 parser completeness 和 artifact refs，不能用目录存在性代替。

风险 4：API、CLI 与未来 TUI 渲染漂移。缓解：所有调用面以同一 service/envelope 为输入，API/CLI parity 与 TUI adapter tests 是门禁；TUI 不通过解析人类文本获取状态，直接调用 Python API 或结构化 CLI envelope。

风险 5：上层要求 task-id 或平台状态。缓解：外部 ID 仅进入 adapter metadata；Forge 的 operation_id、workspace 和 artifact refs 保持平台无关。

非阻塞开放项：各 task pack 的具体参数字段和首批 stable capability 名单在后续 PLAN 中细化；它们不得改变本设计的双稳定面、operation identity、execution/collection 状态、事实/解释边界、service/engine 边界或兼容约束。

本地 SPEC 是唯一规范源；远程审阅副本如有，仅为非规范镜像。实现与变更必须通过本 SPEC 派生的 PLAN 和验证门禁。
