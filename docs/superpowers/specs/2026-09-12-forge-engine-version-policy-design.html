摘要与修订依据

Forge 是面向人类研发者与不同类别 Agent 的、协议和平台无关的 ABACUS 科学计算单元操作基座，同时提供非交互 CLI 与 Python API。Paimon v1.2 → v1.3 是主要迁移消费者，不能以 Paimon 的进程模型限制其他调用方。

保留 2026-09-12 的方向裁决：abacuslite 作为内部解析/写入后端、collect 优先、可选依赖与 native 默认；PyATB 双命名兼容、保持既有 final-structure 候选与优先级；LTS/develop 双轨发布证据；工具级迁移矩阵由 Paimon adapter 维护。2026-09-13 本人确认审查发现并授权优化本文；当前实现已经完成 Stage 0 的调用配置、局部分发、版本来源和离线 parity，本文仍是后续发布与迁移验收的规范源。

当前基线：Forge 代码提交 6654001 与 cf5b2774283254c91d00f94bdee690bbfc3c9ae8；ABACUS/abacuslite 94576a80169de36e02e637edc2a0963fba9e1838；app-tools 配对证据提交 d149294d。Stage 0 证据记录 canonical checkout 的 15 项 parity 与 Forge 全量离线回归；Stage 5 历史证据仍记录 develop 9 passed、LTS 1 failed + 8 passed，失败为 typed cell-relax collection 未达到 complete；具体原因须核对原始 diagnostics，不能仅由缺少 STRU_FINAL 推断。

目标与非目标

  • 为 typed scf/relax/cell-relax/md collect 增加可替换 parser backend，保持事实、来源、状态和审计语义；CLI 与 Python API 行为一致。
  • 明确 LTS/develop 支持的版本、capability、基组与预期状态；版本支持不等于每个 capability 都能完整收集。
  • 以 prepare/modify/execute/postprocess/collect/export 单元边界承接可复用旧依赖职能，区分当前可用、实验性、待补齐与外层责任。
  • 不接入 ATP/MCP、Slurm、站点资源、报告 UI 或科学接受判断；不在本批次实现 prepare backend、改变 final-structure 候选政策或翻转默认 parser。
  • 不在 Forge 内 vendor abacuslite，不从 atst-tools 的副本导入；不把可选 backend 发布进度变成 native Forge 发布前置条件。

决策与替代方案

1. 内部 parser backend，collect 优先。上位 R7 的 engine adapter 是 ABACUS/PyATB/ATST 程序接入边界；本次在 ABACUS collection 内部新增解析接缝，不能宣称现有 runner protocol 已提供可替换 parser。现有 collect service 直接调用 collection 基元，实现时在该边界注入后端，并共用 typed 事实投影。calculator、ASE Atoms 与上游全局变量不进入公共结果。

直接调用 abacuslite.io.latestio 或 legacyio 的读取函数，按每次 operation 的输出版本选择局部函数引用；不实例化会探测/运行 executable 的 calculator，不调用全局 switch_io_backend_version。若原始读取函数仍有不能隔离的状态或副作用，先阻断可选后端发布并补设计，不假定 CLI 进程隔离足够。native、CLI 和长期驻留 Python API 均受同一契约保护。

2. canonical → 兄弟消费者。abacus-develop/interfaces/ASE_interface/abacuslite 为 canonical；atst-tools 保持自身 vendored-sync；Forge 直接消费发布包。阶段 0 在开发 harness 中指向明确 commit 的 checkout，不修改发布依赖元数据。阶段 1 待可安装发布包存在后，将 extra 写为该实际版本的 abacuslite==版本号，禁止同时写成 >=1.0。升级需 fixture parity、extra 安装和双轨证据。

PyPI 可用性在阶段 1 启动时重新核验；不把历史 404 当作持续事实，也不把 git direct reference 的索引接收规则归因于 PEP 508 语法本身。默认包保持轻量；不采用 vendor、兄弟仓副本导入或核心硬依赖。

3. 兼容版本文件名，保持事实语义。补齐 PyATB 矩阵名称识别与显式 handoff 回归；增加 LTS relax_steps 标记。沿用 relax_results.py 的既有 contained 候选：STRU_FINAL、STRU_FINAL.cif、STRU_ION_D、STRU_NOW、STRU_NOW.cif、STRU.cif、STRU。存在 native final 家族时只在该家族选择；否则沿用旧候选。候选必须唯一且可解析，普通 inputs/STRU 和 reports 下文件继续排除，inputs/OUT.* 沿用现有领域输出边界。满足其他收集条件时，唯一有效旧候选继续允许 collection=complete；缺失、歧义或不可解析保持 partial。此处 final 是既有收集契约中的文件事实，不新增科学接受含义。轨迹最后一帧不得自动生成 final artifact；改变候选政策另立窄 SPEC。

4. 双轨门禁验证预期行为。使用精确 ABACUS commit、可执行文件完整 SHA-256、构建选项和输入身份绑定发布证据。工作区 abacus-packages 是本地复现基座，不是可安装 Forge 的依赖或固定目录要求。LTS/develop 标签只指当次验证的版本；升级需重跑，不泛化为任意历史或未来版本。

本机 smoke 验证进程、解析、containment 与 artifact。Paimon 的 GPU 默认、SIF 初始化、MPI 资源和生产链路由 app-tools adapter 与外层 E2E 验证；本地串行或 MPI smoke 不替代生产验收。

5. Forge 发布与 Paimon 迁移分别验收。Forge 承接可复用输入准备/编辑、本地执行、结果收集与独立后处理/导出事实基元；兼容 fixture 是迁移证据，不是运行时职能。“两包未涵盖”不作未经逐项调查的断言：typed MD postprocess/export、property manifest、PyATB handoff、ATST adapter 与追加审计是 Forge 的当前扩展面，其中实验性能力不得写为稳定覆盖。

工具矩阵由当前生产仓 app-tools/toolbox/ABACUS 的 Paimon v1.3 adapter 维护。拟建规范入口为 app-tools/toolbox/ABACUS/docs/superpowers/specs/paimon-v1.3-forge-coverage.html（尚未创建，须在迁移工作中建立并接入该仓索引）。不得将历史 paimon/ 仓或模糊的“Paimon v3 adapter 仓”作为责任落点。

每行记录：v1.2 工具/旧包具体调用 → 所需 Forge capability/operation 与 CLI/Python 入口 → 当前成熟度及证据 → adapter 编排/资源/报告责任 → 缺口 owner/跟踪项 → 迁移状态。基元缺口归 Forge；协议、工具编排、资源、展示与科学判断归调用方。基元契约与两种入口同时可用，不要求工具与 capability 一一对应。

起始调查必须包括现有 BandData、PDOSData、COHP RESULT/输入处理与 convergence PrepareAbacus/RESULT 消费。Forge 的 clean install 只证明本包脱离旧依赖；Paimon v1.3 发布必须另有目标工具运行路径的直接/间接旧包依赖清零，以及已有 ABACUS Agent Benchmark 同等或更好的证据。该跨仓门槛不改成 Forge 每次发布门禁，但未满足时不得宣称迁移完成。

事实提取与后端职责

parser_backend 仅选择下表中的可替换数值读取层。共同事实提取对两种配置执行同一实现；它不先运行 native collector，也不在 abacuslite 缺值时补跑 native。每个公开字段只有一个提取责任方，阶段 0 PLAN 将既有字段逐项映射到下表并给出单位、来源和缺失语义。

责任层事实与边界
共同来源与文件事实复用 contained 来源发现、日志歧义、INPUT/结构快照、final 候选选择、artifact 索引、time.json 与已有报告/能带/DOS 等 sidecar 解析；保留各自来源和现有公开事实。
共同日志事实电子收敛标记、已有运行观察、relax/scf 步数和计数、stdout 运行时事实、MD 原生温度/总能/势能/动能/压力序列与 MD_dump 帧/步数。MD 热力学继续只取 running_md.log，MD_dump 可选，不以轨迹代替热力学日志。
可替换数值读取主 running log 的电子 total_energy、fermi_energy、力、应力由所选 backend 独占读取；abacuslite 适配器调用对应局部底层函数，保留电子能与 MD 含离子动能的总能区别。允许为该 backend 编写明确的格式/缺失归一化，不调用另一 backend 补值。现有 stdout 电子标量补充规则抽为共同来源仲裁，只在既有来源条件下生效，不能因某 backend 解析失败而启用。
共同派生与交付从已选事实推导 energy_per_atom、压力与力/应力汇总，复用单位、来源引用、非有限值、typed observations/status 及审计投影；不追加新科学判断。

abacuslite 的 read_abacus_out 会额外要求 eig_occ.txt、MD_dump 和轨迹/电子态帧数一致，本批不把它作为四 capability 的通用入口；优先使用接受日志行的底层读取函数。不得将这些辅助文件升级为 Forge 最小 collect 的前置条件，也不得把上游默认补零当作报告事实。压力符号、单位和末步选择按 Forge 同源 parity 校验。可识别的数值缺失仍返回部分事实；若底层函数无法满足既有公开语义，阻断可选后端交付并处理其实现缺口，不降低 parity 标准或隐式 fallback。

调用层配置（Stage 0 已实现；Stage 1 发布门禁仍待验收）

ScfServiceSet、RelaxServiceSet、MdServiceSet 的构造与 default 工厂已新增 keyword-only parser_backend="native" 和 output_version=None；配置保存在 service 实例中，仅供 collect 使用，不修改进程环境。CLI operation collect 已新增 --parser-backend native|abacuslite 与可选 --output-version，构造相同 service 配置；CLI 在其他 operation/capability 显式使用这些选项返回 request.invalid；Python 实例配置仅在 collect 调用时校验，其他 operation 不消费该配置。legacy facade/API/CLI 保持既有路径。行为证据见 Stage 0 evidence。

这里的 parser_backend 不替换已有描述 ABACUS/PyATB 计算程序的 engine 字段。v1 request JSON、capabilities/schema 文档和 workspace schema 不增加配置字段；配置属于新增的调用接口，必须在 README、Python 用法和 CLI help 说明。默认始终 native，安装 extra 不自动改变行为；本批次不引入 auto 模式。

版本解析与 provenance

abacuslite 选择使用被收集的 contained running log 中的生产者版本，不运行本机 abacus --version。output-only workspace 无需 INPUT 或已安装 ABACUS。调用方可在日志无版本时显式提供 output_version；若与日志识别结果冲突则拒绝，不能覆盖冲突。来源歧义沿用原 collector 的拒绝/partial 规则，不任选一个目录。

版本正规化保留原始字符串，显式支持测试覆盖的 v3.10.1、v3.11.0-beta8+56 等形式；构建后缀不得传给只接受窄格式的上游全局切换函数。映射为纯函数：已识别的 3.9 develop 格式及 3.11 系列选 latestio；已支持的 3.x legacy 版本（包括裸 v3.9.0）选 legacyio。映射范围需有 fixture 证据；v2、未知格式和未经支持的新主版本不按 minor 大小猜测。

存在唯一非空主日志时，abacuslite 无版本且未显式指定、日志版本格式未知或未支持均返回 precondition.missing；缺日志、歧义来源等重叠情况按错误章节的顺序处理。native 保留既有无版本/不支持版本的解析行为，不凭版本新增拒绝；显式 output_version 的无效格式或与日志冲突仍是调用错误。两种路径的 OperationOutcome（含 partial/missing_output）在既有 diagnostics 的 parser 对象记录 requested_backend、actual_backend、backend_version（native 为 Forge 版本）、io_backend、output_version_raw/normalized、version_source（log/caller/unknown）及日志相对来源；阶段 0 另记 abacuslite commit。未调用数值后端时 actual_backend/io_backend 为 null，其他未知信息为 null，version_source 为 unknown；不把共同提取标成 native fallback。

成功与部分收集的 event 沿用既有 envelope 持久化上述对象。ForgeErrorEnvelope 保持现有字段：错误原因与已知版本信息放入 message，affected_fields 指向 parser_backend/output_version/workspace_rel 等实际受影响项，不增加 diagnostics、嵌套 outcome 或新失败事件。绝对 checkout 路径不进入公开诊断。版本冲突比较正规化的版本身份，保留预发布和构建后缀；不同已知后缀不视为相同。等价写法（如 beta.8 与 beta8）的正规化由 fixture 固化，不将 LTS/develop 标签接受为 output_version。

矩阵 handoff 的角色

2026-09-13 源码复核校正：pyatb_typed.py::prepare_typed_pyatb_band 接受显式矩阵路径，build_prepare_pyatb_manifest 按请求角色覆盖名称分类；旧名称列表位于 pyatb_manifest.py::classify_pyatb_output。因此历史证据中“typed handoff 只消费旧名”的归因不能直接作为事实。R3 先用真实新名来源验证已有链路，补齐分类别名及缺失回归；仅修复复现的断点，不凭历史描述增加 rename 或输入白名单。

错误与回退语义

新配置的检查按下表顺序执行；既有 request/path/profile 校验与 operation_id 冲突规则保留。调用层配置只影响 collect：Python service 实例上的配置对 prepare/modify/execute 不生效；CLI 在非适用 operation/capability 显式传入选项则于 admission 前拒绝。

顺序与条件返回与优先级审计
1. 参数值/类型无效、调用方版本语法无效，或 CLI 选项用在非适用操作request.invalid，exit 2；不探测后端包或读取输出。Python 构造保存配置，在 collect 调用校验并返回同形 error。admission 前拒绝，无 event。
2. 合法 collect 受理后，显式 abacuslite 包不可加载缺包或已识别的依赖不可用为 precondition.missing，exit 3；优先于缺输出。意外导入实现异常为 internal.failure，exit 5。保留 admission，不写 outcome event。
3. 没有唯一非空 contained 主日志（包括缺失、空日志、歧义）不分发数值后端、不要求版本；共同事实按该 capability 既有规则返回 collection 状态，通常为 missing_output/partial，exit 0；若既有规则允许仅凭 stdout 等来源 complete，保留该行为。调用方版本不能消除来源歧义；stdout 已有可解析事实沿用共同规则。一个 OperationOutcome event，parser 的 actual_backend 为 null。
4. 唯一非空日志的已识别版本与调用方版本冲突request.invalid，exit 2；先于支持范围判断，两种 backend 相同。已受理，保留 admission，无 outcome event。
5. 唯一非空日志无版本且未提供版本，或日志版本未知/不支持abacuslite 返回 precondition.missing，exit 3；包括截断后版本缺失。日志无版本时才使用有效的调用方版本，仍须在支持范围内；识别出未知版本串不能被调用方覆盖。native 继续既有解析行为。class 3 保留 admission，无 outcome event；native 按正常 outcome 记录。
6. 已选择可用后端，日志截断、数值缺失或 optional 文件缺失保留可确认事实，按 owning collector 规则 complete/partial/missing_output，exit 0；缺数值不触发另一后端。意外实现异常 exit 5。正常 outcome 追加一个 event；内部异常仅保留 admission。
  • 未配置即 native，不是失败后回退。显式 abacuslite 缺包、版本未知/不支持返回 precondition.missing（exit 3）；无效配置或版本冲突返回 request.invalid（exit 2）；不静默降级，不运行两个完整 collector 后覆盖或拼接结果；共同提取的允许范围见架构职责表。
  • 缺失领域输出按上表第 3 行，版本已可分发后的截断日志或 optional 文件缺失按第 6 行投影；只有可识别的解析缺失可归一化，不能把任意异常吞成空结果。意外实现异常保持 internal.failure（exit 5）；沿用原 admission、事件与错误持久化规则。
  • 版本 unsupported 的前置条件失败与可解析输出的 collection=partial 区分；collection 部分不冒充执行失败。collect 不启动 ABACUS，不改变 scientific=unassessed。
  • 解析必须只读领域来源；新 backend 若有已证实的副作用，先修复上游或另行设计 contained 快照并验证来源映射。不能用先复制后任意读取绕过 containment；本批次不因未复现的 unlink 指控强制快照。
