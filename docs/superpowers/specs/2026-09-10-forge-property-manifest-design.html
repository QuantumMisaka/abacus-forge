摘要

Forge 当前的 convergence、cube、workfunc、vacancy、BEC 与 Bader property pack 仍是 legacy TaskResult 面。它们能完成本地输入生成、子目录执行和文本/cube 后处理，但 TaskResult.artifacts 只是“路径 → 绝对路径”映射，不能稳定表达某个 cube 是输入还是派生结果、属于哪个自旋通道、是否可读以及来源是什么。abacus-agent-tools、abacus-test 和 abacuscopilot 的现有实现也说明，cube 文件名和输出目录存在变体；仅凭目录扫描或文件名猜测不能形成可靠的机器事实。

本设计提出一个兼容性增量：在 legacy property 的 JSON 结果 diagnostics 中增加 capability-specific 的 property_manifest，首批覆盖 charge-density、spin-density 和 charge-diff 的 cube 输入、派生 cube 与报告文件。它不是新的 typed capability、不是新的事件或持久化状态机，也不改变旧的 TaskResult 字段和 CLI 语义。

拟议结论：让机器和人类都能拿到“实际处理了哪些文件以及文件事实”的稳定索引；科学结果的接受、任务编排、重试和平台调度仍由人类或 Agent 负责。

目标与非目标

目标

  • 为首批 cube property post 操作提供版本化、可 JSON 解析的 source/derived artifact 事实。
  • 记录 workspace-relative 路径、有限的文件类型、来源/派生关系、自旋事实、哈希、大小和解析状态。
  • 区分缺失、resolved symlink 越界和不可读取文件，不为不存在的文件伪造 artifact。
  • 让 Python API 与旧 property CLI 使用同一 manifest builder，并保持既有返回字段和有效输入行为不变。

非目标

  • 不新增或推广 typed property capability，不把 legacy pack 伪装成 Stage 4 稳定面。
  • 不修改通用 forge.result/v1、ArtifactRecord、TaskResult 字段、事件/admission 或旧 CLI 的 prepare|run|post 语法。
  • 不把目录扫描、latest 选择、文件名猜测、SCF→property workflow、重试/恢复或平台调度写入 Forge。
  • 不输出科学接受/拒绝、收敛、质量或物理解释；manifest 只描述事实。
  • 本切片不覆盖 workfunc、ELF、Bader、vacancy、BEC、nspin 4 或真实 ABACUS smoke；这些按各自证据另行推进。

R1manifest 只作为 diagnostics.property_manifest 的新增字段，根对象的 schema version 固定为 forge.property-manifest/v1，包含 task、inputs、outputs、missing 三个数组。旧 TaskResult.to_dict() 键与旧 CLI 输出保持不变；新增字段可被忽略的旧消费者不失败。
R2present entry 至少包含 path_rel、kind、role、origin、spin、artifact_id、sha256、size_bytes 和 media_type；parse_status 若存在只能是 ok|malformed，首批成功解析的文件标记为 ok。首批不把 legacy parser 异常改造成结构化降级；未来若要产出 malformed，必须另行设计降级行为。同一 workspace 内的 entry 与现有 envelope artifact path/hash/size 对齐；哈希和大小来自实际文件。
R3首批 kind 只使用 cube、report、text、other；role 为 input|output；origin 为 source|derived；spin 为 shared|up|down|unknown。property 语义由 root task、显式 role 和 spin 表达，不根据文件名臆测新的科学种类；调用方显式交接的额外文件可用 other 保留，但未交接的文件不因 manifest 而被扫描。charge/spin/charge-diff 的映射测试覆盖 shared、up、down 和 unknown；显式额外文件仍可见但不会被解释成新 property。
R4missing entry 只包含路径、kind、role、origin、spin 和 reason；reason 固定为 missing|escaped|unavailable，不得带 artifact id、哈希或大小。首批中 legacy parser 抛错的文件沿用原异常行为，不伪造 manifest entry。缺失文件、外部 resolved symlink、文件消失和哈希读取失败测试分别得到对应 reason；不存在的 artifact 不被伪造。
R5对由输入数据实际派生的 origin="derived" 文件（首批为派生 cube）必须记录非空 source_artifact_ids；事实报告等只记录操作观察的 report 可以不带 source refs。所有 refs 只能引用同一结果中的 present entries；source entry 不需要反向引用。不得引入跨 operation 的 ArtifactRef、任务 DAG 或 provenance 数据库。spin-density 的差 cube 引用两个 source cube；charge-diff 的差 cube 引用 full/subsystem1/subsystem2；degraded 情况下 metrics report 不伪造来源；引用不跨 workspace。
R6manifest builder 接收 property post 已经选定的显式路径和语义，不新增目录扫描或 latest 规则；既有 legacy 选择逻辑在本切片保持兼容，manifest 只报告实际选择。无文件时只使用下表冻结的 canonical expected path，不复制 glob 变体。路径中的 <suffix> 取对应子任务 inputs/INPUT 的既有 suffix 值；缺失或空值使用 ABACUS，不安全值不被拼入越界路径。同一 workspace、同一 legacy API 调用和同一 CLI 调用得到等价 manifest；无输入或越界路径时只记录事实并保留既有 status/diagnostics 边界。
R7所有 manifest 路径都须通过既有 workspace containment；manifest 是 diagnostics 增量，投影失败不得把原本成功的 legacy post 变成异常、改变 status/exit 或自动重试。实现应保留原结果并记录可 JSON 化的 manifest warning。路径安全、JSON finite、legacy 回归、投影失败回归和完整离线门禁通过；不产生网络、调度器或 sibling-repository import。

设计决策与替代方案

D1：放在 legacy diagnostics，不新增 typed property capability。当前 property pack 的消费面仍是 TaskResult 和现有 CLI；直接改通用 ArtifactRecord 或一次性设计所有 property operation 会把尚未有真实证据的能力锁成公共契约。diagnostics 增量可以服务上层 Agent，同时保留迁移余地。

D2：使用明确的 source/derived 文件事实。首批 post 函数继续负责兼容性选择，manifest builder 只接收选择结果、canonical expected path 和调用方确认的语义；它不自己扫描目录、不选择 latest、不从文件名推断新的 property。

D3：kind 保持文件类型级别，task/role/spin 表达有限语义。cube 的 charge、potential、ELF 等科学种类不进入通用 kind 枚举；后续若某个 pack 需要更细语义，另起 capability-specific SPEC。

D4：artifact id 只在当前结果内有效。manifest 与已有 envelope 使用同一路径事实和 artifact projection；跨 operation 的来源引用仍由人类/Agent 组合，不在这个 legacy 增量中建立 DAG。

替代方案：扩展通用 ArtifactRecord 被否决（影响全部 capability）；马上新增 typed property capability 被暂缓（输入、执行、collect、postprocess 及真实证据尚未分别冻结）；新增独立 manifest 文件被暂缓（会引入第二份持久化协议）。

架构与数据流

legacy property prepare/run/post
             │
             ├─ existing compatibility selection / cube arithmetic
             │       └─ selected source + derived paths and parser facts
             ▼
     property_manifest builder (explicit facts only)
             │
             ├─ workspace containment + hash/size/media projection
             └─ diagnostics["property_manifest"]
             ▼
       existing TaskResult.to_dict / legacy CLI JSON

  • 层次边界：Forge 只交付文件和解析事实；Paimon/人类/Agent 决定是否继续执行、如何编排和是否接受科学结果。

错误处理

  • 文件不存在、resolved target 越界或不是普通文件：进入 missing，reason 分别为 missing、escaped 或 unavailable；不读取越界文件。workspace 内声明但 resolved target 越界的 symlink 保留其 lexical workspace-relative path_rel，不记录外部 resolved target。
  • 文件存在但读取/哈希失败：进入 missing，reason 为 unavailable；不制造 artifact id。
  • 首批文件存在但 parser 发现结构不完整时，沿用当前 legacy parser 异常行为；manifest 不声称已经记录该文件。结构化 parse_status="malformed" 只有在后续计划明确捕获、降级和兼容策略后才能启用。
  • manifest 自身投影/序列化失败：保留原本的 legacy TaskResult 和 status/exit，并以 diagnostics warning 说明 manifest 未生成；不自动重试，不改变其它已有结果字段。

测试

  • 契约：根键、schema version、枚举、strict/round-trip、present/missing 互斥字段、finite hash/size 和 optional source refs。
  • cube：首批三种 property 的 source/derived 映射、nspin 1/2、grid mismatch、finite/path/symlink 行为；使用当前 CubeData 单场边界，不解析负 natoms 轨道 cube。首批不改变 malformed parser 的 legacy 异常路径。
  • 兼容：现有 tests/test_maturation_packs.py、CLI property tests、legacy result tests 和 architecture gate；旧 JSON 断言只在新增 diagnostics 允许的地方增量更新。
  • parity：同一隔离 fixture 通过同一 legacy Python property API 和现有 CLI 得到等价 manifest、路径、hash、status 和 diagnostics；不新增用户路径参数，不启动真实 ABACUS。
  • 最终门禁：conda run -n paimon env PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python -m pytest -q -p no:cacheprovider、git diff --check；real-smoke/benchmark 仍单独 opt-in。

风险与开放项

已知风险：不同 ABACUS/abacustest 版本可能使用不同 cube 文件名、输出目录或 z-fastest 标记；本设计只记录 post 实际选定的路径，并在没有选定文件时使用上表 canonical expected path，不扩张自动发现规则。

需要用户确认的唯一公共决策：是否接受“legacy property pack + diagnostics.property_manifest 增量、首批 charge/spin/charge-diff、上表 canonical 路径、通用 ArtifactRecord 与旧 CLI 不变”的形态。若接受，后续 PLAN 只需冻结 builder 的内部输入、测试矩阵和 malformed 降级策略；若不接受，应在实现前改写本 SPEC。
