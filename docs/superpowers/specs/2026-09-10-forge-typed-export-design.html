ABACUS-Forge typed export

日期：2026-09-10　状态：Approved

实现状态：typed export 已按本 SPEC 与对应 PLAN 完成代码实现和 Task 级审查；当前仍为 experimental，本状态不构成真实 ABACUS 运行或科学验证证据。

摘要

Forge 已有 typed operation、workspace event、ArtifactRecord 和 ArtifactRef；本 SPEC 在保留 legacy 行为的同时，新增一个独立、显式来源、可审计的 typed export operation。

核心决策：首版 typed export 是“显式来源的结果 JSON 文档导出”，不是 最近结果发现器，也不是二进制 artifact 打包器。请求显式给出同一 workspace 内一个既有 operation 的 ArtifactRef 列表；Forge 解析对应 immutable event，验证这些 refs 确实属于该 outcome，然后在当前 workspace 内原子写出一个新的 forge.export/v1 JSON 文档，并将该文档作为新的 output artifact 记录到 export event。

这保持了 legacy export(result) 的“结果序列化”直觉，同时让 Agent 获得 显式来源、路径 containment、冲突语义和审计证据。二进制复制、压缩包、多 operation 聚合和发布报告另行设计。

依据与边界

  • 2026-09-01/09-02 approved Forge SPEC 已冻结 export operation、 workspace-relative artifact、event 和 facts-only 边界。
  • 现有 legacy api.export() 可写任意目标、静默覆盖、不产生 event；这些 行为只能留在兼容入口，不能复制到 typed service。
  • 现有 ArtifactRef 只表达 {operation_id, artifact_id}，不改变 它的字段；typed export 通过 workspace event payload 解析 ref，不增加 task ID、 workflow edge 或平台字段。
  • 科学验证、结果接受、任务编排、重试/恢复、平台调度和发布策略均由人类或 Agent 负责；export 只交付序列化事实。

目标与非目标

目标

  • 新增显式 typed export request、Python service、machine CLI route 和 discovery/schema descriptor。
  • 只从显式 ArtifactRef 解析一个既有 operation outcome；同一 workspace、 同一 source operation，ref 必须真实存在于该 event 的 envelope。
  • 只支持 format="json"；目标为 canonical workspace-relative 文件，默认 overwrite_policy="fail"，已存在目标不得静默替换。
  • 输出 JSON、output artifact、artifact refs、operation event 和 API/CLI 等价事实。

非目标

  • 不读取 latest event、目录中的“最近结果”或未声明文件；不隐式执行 collect、 postprocess 或任何上游 operation。
  • 不复制 artifact bytes、不制作 zip/tar、不跨 workspace 读取、不接受绝对路径。
  • 不生成科学报告、接受/拒绝结论、平台发布记录、调度状态或 workflow 关系。
  • 不改变 forge.result/v1、forge.operation-outcome/v1、 ArtifactRecord、ArtifactRef、legacy API/CLI 或既有错误值。

Typed request

请求使用既有 forge.request/v1 顶层字段，并显式声明 capability="export" 与 operation="export"：

{
  "schema_version": "forge.request/v1",
  "capability": "export",
  "operation": "export",
  "operation_id": "123e4567-e89b-42d3-a456-426614174123",
  "workspace_rel": "runs/Si_scf",
  "source_artifact_refs": [
    {"operation_id": "123e4567-e89b-42d3-a456-426614174010", "artifact_id": "artifact-energy"}
  ],
  "destination_path_rel": "exports/scf-result.json",
  "format": "json",
  "pretty": true,
  "overwrite_policy": "fail"
}
字段约束语义
source_artifact_refs非空数组；每项是既有 ArtifactRef；所有 operation_id 相同来源 operation 与需要显式证明的 artifact 集合；不接受跨 operation 聚合
destination_path_relcanonical workspace-relative 文件路径新 export JSON 文档的位置；父目录可由 service 创建
format当前唯一值 json输出 forge.export/v1 文档
pretty布尔值，默认 false只改变 JSON 空白，不改变文档语义
overwrite_policy当前唯一值 fail目标存在即 request error；replace/merge 需另行 SPEC

Export document

目标文件是可移植的单 JSON 文档。它保留来源 outcome 的完整事实，并把请求中的 refs 固定写入文档；它不声称复制了来源文件内容。

{
  "schema_version": "forge.export/v1",
  "source_operation_id": "123e4567-e89b-42d3-a456-426614174010",
  "source_artifact_refs": [
    {"operation_id": "123e4567-e89b-42d3-a456-426614174010", "artifact_id": "artifact-energy"}
  ],
  "source_outcome": {
    "schema_version": "forge.operation-outcome/v1",
    "operation_id": "123e4567-e89b-42d3-a456-426614174010",
    "envelope": {
      "schema_version": "forge.result/v1",
      "operation": "collect",
      "workspace_rel": "runs/Si_scf",
      "status": {"execution": "not_run", "scientific": "unassessed", "collection": "complete"},
      "artifacts": [{
        "id": "artifact-energy",
        "path_rel": "outputs/energy.dat",
        "role": "output",
        "stage": "collect",
        "availability": "available",
        "media_type": "text/plain",
        "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
        "size_bytes": 32
      }],
      "metrics": [],
      "checks": [],
      "warnings": [],
      "diagnostics": {}
    },
    "observations": []
  }
}

source_outcome 必须是从 immutable event payload 解码后重新序列化的 exact outcome；export 不重新计算 metrics、不重写 status、不添加 scientific 判断。 source_artifact_refs 是 provenance/selection facts，消费者可据此选择 envelope 中的 artifact。

来源解析与数据流

typed ExportRequest
  │
  ├─ validate request, containment and reserved paths
  ├─ admit export operation_id (existing operation guard)
  ├─ resolve source operation_id in reports/forge-workspace.json
  ├─ read exactly that reports/events/*.json payload
  ├─ verify every ArtifactRef against source envelope.artifacts
  ├─ atomically write destination forge.export/v1 JSON
  ├─ build one output ArtifactRecord (hash/size, stage=export)
  └─ existing ServiceContext.persist → artifact_refs + one export event
  • manifest index lookup是按显式 operation_id 的定点解析，不是 latest/排序扫描；事件 path 必须来自 workspace manifest 且仍 contained。来源 ArtifactRecord.path_rel 只按历史记录校验为 canonical/contained，不要求来源文件当前仍存在，也不重新读取或 比对当前 hash。
  • 源 event 和目标文件必须位于当前 workspace；ArtifactRef 的 operation_id 不携带外部 workspace，因此跨 workspace ref 直接拒绝。来源 artifact 文件本身是历史事实，删除、 修改或替换不会被 export 隐式重新解释。
  • source event 只读；export 不修改源 event、源 artifact 或上游状态。
  • 目标不得覆盖 reports/forge-workspace.json、reports/events、 reports/claims、锁文件、兼容审计文件、源 artifact 或其父级审计目录。

Typed outcome

  • 成功返回既有 forge.operation-outcome/v1，operation 为 export，execution="completed"、collection="complete"、 scientific="unassessed"。
  • envelope 只包含新写出的 JSON output artifact；其 path_rel、hash、size 来自同一写入结果。diagnostics 记录 source refs、source operation、destination、 format 和 overwrite policy。
  • 持久化仍由现有 ServiceContext.persist() 单点注入 export operation 的 artifact_refs 并追加一个 event；不直接写第二份 event 或修改 source event。
  • API 与 machine CLI 走同一 service。CLI stdout 仍是单 JSON outcome/error， --pretty/--format=text 只改变显示。

错误与退出语义

情形Forge error class / exit副作用
字段、schema、ref 数组形状或 format 错误request.schema / 2不 admission、不写目标、不写 event
workspace、source/target 非 canonical、越界、symlink escape、保留审计路径request.path / 2不写领域文件
source event、source outcome 或请求的 artifact ref 不存在/不可解码precondition.missing / 3在 admission 后发现时保留 admission tombstone；使用新 operation_id 重试
目标已存在且 policy=fail，或目标与源 artifact 冲突request.invalid / 2不覆盖目标；已 admission 时不写成功 event
重复 export operation_idoperation.conflict / 2不触碰源或目标
目标/事件/manifest 持久化失败persistence.failure / 5按既有规则保留 admission；不自动重试
其他 Forge 内部异常internal.failure / 5按既有 tombstone 规则处理

export 本身不启动外部进程；不存在 process returncode 或科学失败判断。目标写入若已 成功而 event/manifest 之后失败，继续沿用既有持久化失败语义，不以同一 operation_id 自动重放。

兼容、发现与成熟度

  • 新增 discovery capability export，只宣称 operation export、 engine forge、maturity experimental、input/output artifact roles 和上述 request schema。
  • 无 capability 的机器 operation export 请求继续按现有未支持路径返回 request.invalid/2；legacy 顶层 abacus-forge export 的隐式 collect、任意输出路径和默认 JSON 保持不变。
  • 本设计不提升任何 ABACUS/PyATB capability 的 maturity，也不构成真实计算或科学 验证证据。

验收与门禁

  • contract：request、ArtifactRef 列表、forge.export/v1 文档 round-trip， unknown field、非 JSON、绝对/越界路径、混合 operation ref 和仅支持 JSON 的拒绝。
  • source resolution：明确 operation event、缺失 event、坏 payload、缺失 artifact、 外部 symlink 和跨 workspace ref；不触发 collect/postprocess。
  • destination：父目录创建、contained target、audit/source overlap、已有目标、 atomic write、hash/size 与输出 artifact 一致。
  • service/event：admission、单 event、source event 不变、失败 tombstone、artifact refs 单点注入和科学状态始终 unassessed。
  • API/CLI parity：隔离 workspace 中同一 request 得到等价 outcome、目标文件、诊断和 event；stdout 单 JSON，text/pretty 不改语义。
  • compat/architecture：legacy export/API/CLI 回归、discovery/schema、forbidden-import AST gate、全量离线 pytest、git diff --check；不把 fake 或 legacy smoke 当作真实科学证据。

替代方案与后续边界

  • 隐式 latest/result 文件：否决；不可审计且会把 workspace 状态变成 隐藏协议。
  • 直接修改 ArtifactRecord 增加 export 字段：否决；扩大通用 v1 契约， 本切片只在 export diagnostics/document 中表达来源。
  • 二进制 artifact copy 或 archive：暂缓；它需要目标目录布局、冲突、 link/copy 和多文件原子性的新契约，另立 SPEC。
  • 多 operation 聚合：暂缓；当前所有 refs 必须来自一个 source operation， 上层负责跨 operation 编排。

决策记录

决策已收敛：typed export 首版按“显式来源的结果 JSON 文档导出”落地，不做 artifact 文件复制/打包。批准来源为本线程持续推进 Forge 开发的执行授权；本 SPEC 的公共边界、legacy 兼容和 facts-only 约束保持不变。后续实现按独立 PLAN 执行。
