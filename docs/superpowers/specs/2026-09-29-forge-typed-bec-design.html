摘要

当前 composite `bec` pack 的 `prepare_bec` 将 `berry_phase=1` 写入 SCF INPUT，但 ABACUS 的 berry phase 仅在 `calculation=nscf` 且 `symmetry != 1` 时触发；且每个笛卡尔方向需要独立的 `gdir` NSCF 运行。本 SPEC 定义每个位移子任务内部的四阶段（SCF → NSCF(gdir=1) → NSCF(gdir=2) → NSCF(gdir=3)）目录布局、INPUT 生成、执行序列、原生 polarization 日志解析和 BEC tensor 差分计算。

目标与非目标

目标

  • 为每个位移子任务生成包含四阶段子目录的完整可执行工作区。
  • `run_bec` 在每个子任务内按序执行 4 个 ABACUS 进程（1 SCF + 3 NSCF）。
  • 从每个 NSCF 阶段的 running log 解析 `VALUES OF POLARIZATION` 的 total polarization（`(e/Ω)·bohr` 单位）和 modulus 量子数。
  • 从 plus/minus 位移的 polarization 差分计算 Born effective charge tensor 行。
  • 真实 ABACUS smoke 门禁验证上述管线。

非目标

  • 不在 Forge typed operation 层引入多阶段/多 gdir operation。
  • 不做 polarization 量子 branch 选择（-1/0/+1）的科学判断；返回 parser 事实供上层决策。
  • 不处理 Born charge 的对称化、声学求和规则校验或与参考值比对。
  • 不在 Forge 内实现 SCF→NSCF 的自动续算、重试或工作流恢复。

Charge density 传递

SCF 阶段完成后在 outputs/（或 inputs/OUT.*）目录写出 SPIN1_CHARGE.cube（nspin=1）或 SPIN1/2_CHARGE.cube（nspin=2）。NSCF 阶段以 init_chg=file 从同一 workspace 的输出目录读取。Forge 的四阶段子目录方案要求 NSCF 阶段在 init_chg 中指定 SCF 输出的电荷文件路径，或将 SCF 输出目录的电荷文件复制/符号链接到 NSCF 阶段的期望路径。

Polarization 输出格式

每个 gdir 的 NSCF 在 running log 中输出：

 VALUES OF POLARIZATION

  The Ionic Phase:      0.XXXXX
 Electronic Phase:      0.XXXXX

The calculated polarization direction is in R[N] direction

 P =    X.XXXXXXX  (mod    X)  (   X.XXXXXXX,   X.XXXXXXX,   X.XXXXXXX) (e/Omega).bohr
 P =    X.XXXXXXX  (mod    X)  (   X.XXXXXXX,   X.XXXXXXX,   X.XXXXXXX) e/bohr^2
 P =    X.XXXXXXX  (mod    X)  (   X.XXXXXXX,   X.XXXXXXX,   X.XXXXXXX) C/m^2

其中 (mod N) 为 polarization 量子（奇偶电子体系分别 mod 1 或 mod 2），第一个值为 total polarization（沿 gdir 方向投影），括号内为 Cartesian 分量。

设计决策

决策 1：per-subtask stage 子目录，pack 内串联。

每个位移子任务（如 bec/disp_atom001_x_plus/）内部包含 4 个阶段子目录：

bec/disp_atom001_x_plus/
  scf/           inputs/{INPUT,STRU,KPT,*.upf,*.orb}
  nscf_gdir1/    inputs/{INPUT,STRU,KPT,*.upf,*.orb}
  nscf_gdir2/    inputs/{INPUT,STRU,KPT,*.upf,*.orb}
  nscf_gdir3/    inputs/{INPUT,STRU,KPT,*.upf,*.orb}

run_bec 按 scf → nscf_gdir1 → nscf_gdir2 → nscf_gdir3 顺序在各子目录中分别启动一个 ABACUS 进程。该串联属于 composite pack 层面的 Python 编排，不改变 typed operation protocol 的单操作边界。

替代方案（不采用）：单一目录内重写 INPUT 逐次执行——workspace 审计和 artifact 归属会混淆多阶段产物；也不符合 Forge 的"每次执行在独立 workspace 中产生可引用事实"的设计。

决策 2：SCF → NSCF 电荷文件发现与传递（含 nspin=1/2）。

SCF 阶段执行完成后，pack runner 在 SCF stage 的 ABACUS 输出目录中以 glob 模式 SPIN*_CHARGE.* 发现全部电荷密度文件（nspin=1 通常产生 1 个，nspin=2 产生 2 个；后缀为 .cube 或 .hdf5 由 ABACUS 版本决定）。发现的全部电荷文件以 shutil.copy2 复制到每个 NSCF stage 的输出目录中，保持文件名不变。NSCF INPUT 的 init_chg 设为 file，ABACUS 按默认路径约定从输出目录读取。未发现任何电荷文件时，pack runner 将该子任务的后续 NSCF 阶段标记为 failed 并记录诊断，不启动 NSCF 进程。

该发现-复制规则同时覆盖 nspin=1 和 nspin=2，不需要调用方区分。Forge 不判断电荷文件的物理合理性；只负责文件存在性和复制。

替代方案（不采用）：所有阶段共用一个 OUT 目录——破坏 workspace containment 和 per-stage artifact 归属。

决策 3：native polarization 解析为 typed facts，不做科学 branch 选择。

从 running log 解析以下字段并投影为 forge.result/v1 的 metric/check records：

  • polarization_direction（string: "R1"/"R2"/"R3"）
  • total_polarization_mod_bohr（float: `(e/Ω)·bohr` 单位的 total polarization）
  • polarization_modulus（int: mod 量子数）
  • ionic_phase（float）
  • electronic_phase（float）
  • Cartesian 分量 p_x、p_y、p_z（float，`(e/Ω)·bohr`）

不选择 polarization branch（mod wrap-around 的 -1/0/+1 平移），由上层根据 Born charge 的声学求和规则或其他物理约束自行决定。

决策 4：BEC tensor 差分在 pack post 阶段完成。

post_bec 从每个 ±位移对的三方向 polarization 差分计算单行 Born effective charge：

Z*_{i,α} = Ω / (2·δ) × [P_α(+) − P_α(−)]   （单位：e）

其中 Ω 为晶胞体积（Å³→bohr³ 由 pack 内 ase Atoms 获取），δ 为位移（bohr），P 为 `(e/Ω)·bohr` 单位的 polarization。结果写入 reports/metrics_bec.json。不执行对称化或求和规则校验。

  │
  ├── 对每个 subtask：
  │     1. 执行 scf/       → 正常结束 → 收集电荷文件
  │     2. 复制电荷到 nscf_gdir{1,2,3}/

  │
  ├── 对每个 ±位移对：
  │     解析 3 个 nscf stage 的 polarization facts
  │     计算差分 → BEC tensor 行
  │
  └── TaskResult("bec", completed|degraded, summary={bec_tensors})

Polarization 解析契约

解析器位于 composite/properties.py 的新函数 _parse_polarization_log(log_path)，返回 dict | None。匹配规则：

  • 搜索 VALUES OF POLARIZATION 标记行，向后扫描到下一个空行。
  • The Ionic Phase: 后的浮点数 → ionic_phase。
  • Electronic Phase: 后的浮点数 → electronic_phase。
  • The calculated polarization direction is in R[N] direction → polarization_direction: "R{N}"。
  • 第一个 P = 行（(e/Omega).bohr 后缀）：
    • 第一个浮点数 → total_polarization_mod_bohr
    • (mod 后的整数 → polarization_modulus
    • 括号内三个浮点数 → p_x, p_y, p_z

缺失标记行或数值解析失败返回 None（不抛异常），由调用方决定降级。解析结果不缓存；每次调用重新读取日志。

BEC tensor 计算契约

对每个 (atom, direction) 对，设 P_plus[N] 和 P_minus[N] 为位移后/前沿 gdir=N 的 total_polarization_mod_bohr（N=1,2,3 对应 x,y,z）：

Z*_{atom, direction→axis} = [P_plus[N] − P_minus[N]] / (2·δ_bohr)

其中 δ_bohr = displacement × 0.529177（Å → bohr）。结果为无量纲有效电荷（单位 e）。当任一 polarization 缺失时该行值为 null。不执行 polarization mod branch 修正。

风险与开放项

  • ABACUS 版本差异：LTS v3.10.1 与 develop 的 berry phase 输出格式如存在差异，须在双轨 parity 中发现并正向断言。当前未发现差异。
  • 极性/非极性体系：本 SPEC 假设调用方选择适当的 k-mesh 和位移步长以获得物理合理的 BEC；Forge 不做科学判断。
  • PP 类型兼容：USPP 赝势不支持 berry_phase=true（uspp_support.cpp:44）。Forge prepare 不对此组合做前置校验；ABACUS 进程自身在启动时拒绝并返回错误，Forge 将其如实记录为 execution failed 与诊断。由 ABACUS 自身承担输入合法性校验是更诚实的边界。
  • orbital/PP 路径：stage 子目录的 INPUT 中 pseudo_dir/orbital_dir 须指向 stage 子目录自身的 inputs/（Forge prepared 格式，PP/ORB 在 inputs/ 内部），由 _copy_auxiliary_inputs 自然处理。

本地 SPEC 是规范源；远程审阅副本如有，仅为非规范镜像。
