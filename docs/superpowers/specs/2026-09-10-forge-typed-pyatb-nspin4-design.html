摘要

typed pyatb-band 已经能接收显式的 ABACUS STRU、HR、SR、rR 文件并生成 PyATB 输入。当前请求契约把 HR 文件数直接限制为 nspin，因此尚未支持 PyATB 已有的非共线 nspin=4；发现文档也如实公布了当前实现的 1|2 范围。

本切片把 nspin=4 作为一个最小的 typed handoff 扩展：请求允许 1|2|4；HR 路由数按 PyATB 的实际规则映射为 1|2|1；单个 nspin=4 复数 HR 在 manifest 中使用已有的 spin="shared"。Forge 只交接文件、写入输入并记录事实，不读取矩阵内容、不执行属性计算、不解释自旋纹理。

核心结论：这是一项 capability 内的输入契约修正，不是新的 PyATB property capability；保持 forge.pyatb-manifest/v1、通用 result、事件和 legacy helper 不变。

目标与非目标

目标

  • 让 typed pyatb-band 正确表达 PyATB 已支持的 nspin=4 单 HR handoff。
  • 让 request decoder、discovery schema、prepare 生成的 Input 与 manifest 对同一 cardinality 规则保持一致；discovery 用 JSON Schema 条件表达 HR 数量。
  • 保持 nspin=1/2 的现有行为、请求字段和 artifact/provenance 语义兼容。
  • 通过 API、machine CLI、manifest 和错误路径测试证明该边界，而不声称真实 PyATB 或科学结果。

非目标

  • 不增加 PyATB property selector、Berry/transport/自旋纹理等计算能力，也不解析 HR/SR/rR 的数值内容。
  • 不改变 forge.pyatb-manifest/v1 的 kind/spin 枚举、通用 ArtifactRecord 或 event/result schema。
  • 不把 nspin=4 扩展到其他 capability，不添加 SCF→PyATB 编排、目录扫描、调度、重试/恢复或科学验收。
  • 不修改 prepare_pyatb_band、run_pyatb、collect_pyatb 和 run_band_sequence legacy helper。

需求与验收

ID需求验收信号
N1typed prepare request 的 nspin 只接受整数 1、2、4；布尔值和其它整数继续拒绝。构造、JSON round-trip、request decoder 与 discovery schema 的枚举一致为 [1,2,4]；schema 的 integer 类型也拒绝布尔值。
N2HR 路径数量由 spin mode 决定：nspin=1 或 4 要求恰好一个 HR，nspin=2 要求恰好两个 HR；SR/rR 始终各一个。缺少或多余 HR 在任何文件写入前失败；discovery 用 if/then/else 公开同一条件；三种模式生成的 route 数与请求一致。
N3nspin=4 的 generated Input 写入 nspin 4 和一个 HR_route；HR、SR、rR 均保留显式 workspace-relative route。prepare fixture 检查文本、路径 containment、link/copy provenance 和无部分写入。
N4prepare manifest 对 nspin=4 的唯一 HR 使用现有 kind=matrix_hr、spin=shared；SR/rR 仍为 shared。manifest entry 与同一 envelope artifact id、hash、size 对齐；不新增 spinor 值或 schema 版本。
N5API 与 machine CLI 继续调用同一 typed service；legacy PyATB 面的参数、输出和测试保持不变。typed API/CLI parity、discovery、完整离线 suite 与 legacy PyATB regression 通过。
N6Forge 只交付输入交接和可观察事实；不因 nspin=4 输出 scientific acceptance、property result、workflow relation 或 scheduler state。测试只断言生成文件、manifest、artifact、状态和错误；文档明确 real-smoke/科学判断仍在外层。

设计决策

D1：按 PyATB 的 mode/cardinality 规则，而不是按数值 nspin 复用长度规则。本地 PyATB 的 operate_HR_route 明确规定 nspin=1/4 使用一个 HR、nspin=2 使用两个 HR；Forge 只需把这条既有事实反映到请求校验和输入渲染。

D2：nspin=4 的 HR manifest 使用 spin="shared"。nspin=4 的单个 HR 不拆分成 up/down，沿用 manifest 已有的 shared 值；完整的非共线模式仍由请求和生成的 Input 中的 nspin=4 表达。新增 spinor 会扩大 v1 词汇，而本切片没有需要它的下游事实。

D3：不新增 nspin-specific parser。Forge 不验证复数 HR 的内容格式；PyATB 进程负责读取和报告其输入错误。Forge 只验证显式文件存在、路径 containment、hash/provenance 与生成文本。

被否决的替代方案：继续把 HR 数量等同于 nspin（无法表达 nspin=4）；新增四个 HR 文件或新的 spin 枚举（与 PyATB 实际输入规则不符且扩大契约）；在 Forge 中解析复数矩阵并预判科学有效性（越过 facts-only 边界）。

架构与数据流

PyatbBandPrepareRequest(nspin=4, hr_paths_rel=[hr.csr])
        │
        ├─ contract: expected_hr_count(4) == 1
        ├─ typed handoff: structure + HR + SR + rR
        ├─ generated Input: nspin=4, one HR_route, shared SR/rR
        └─ pyatb_manifest/v1: matrix_hr/shared + matrix_sr/shared + matrix_rr/shared
  • 契约层：集中定义允许值和期望 HR 数量；discovery 通过同一允许值和显式 JSON Schema conditional 公布字段及 cardinality，避免 discovery、服务和 manifest 各自漂移。
  • 交接层：复用现有 typed staging、relative link/copy、hash 和 collision preflight；nspin=4 不读取 sibling workspace。
  • 渲染层：现有 route 列表渲染对一个 nspin=4 HR 已经足够，只需由契约允许其通过；不改变 Input 字段命名。
  • 结果层：现有 manifest builder 根据 HR entry 数量选择 shared/up/down；单 HR nspin=4 自然落到 shared，不改变持久化协议。

错误处理

非法 nspin、HR cardinality、路径或重复 basename 继续使用现有 request/precondition/path 错误映射；machine CLI 仍返回既有 request.invalid/request.schema 与 exit class。缺失、越界、不可读源文件的具体错误语义不改变。nspin=4 的矩阵内容错误只会在上层实际启动 PyATB 时由该进程报告，Forge 不提前伪造科学或计算结论。

任何 preflight 失败都必须发生在首次 staging 前；已有目标文件不得被覆盖。服务 admission、事件持久化和 artifact ref 校验沿用现有通用机制。

测试

  • 契约：nspin=1/2/4 round-trip；nspin=4 单 HR 接受；nspin=4 的 0 或 2 个 HR 拒绝；nspin=3、布尔值和未知字段拒绝；discovery schema 枚举与 decoder 一致，并对 nspin=2/其它已知模式公开 HR cardinality conditional。
  • prepare：nspin=4 生成一个 HR route 和 nspin 4；manifest HR/SR/rR 的 kind/spin、artifact refs、hash/size 和 provenance 正确；link/copy、containment、collision/no-partial-write 保持覆盖。
  • service/parity：隔离 workspace 中 Python API 与 machine CLI 的 request、状态、artifacts、manifest 和 event 等价；不启动真实 PyATB。
  • 回归/门禁：现有 PyATB legacy、machine CLI、contracts、workspace、architecture suites；完整离线 pytest、git diff --check、clean wheel/import gate 按计划执行。

测试证明的是 Forge 的输入交接与结构化事实，不证明 nspin=4 矩阵的科学正确性或 PyATB property 可用性；真实进程 smoke 另行作为发布门禁。

兼容与发布

这是 experimental pyatb-band 的向后兼容扩展：旧的 nspin=1/2 请求 wire 形式和 legacy helper 不变，新增的 nspin=4 请求由同一 forge.request/v1 承载。manifest 仍为 forge.pyatb-manifest/v1；旧版本 decoder 可能拒绝 nspin=4，新请求须由 discovery 明确公布 nspin=4 的版本处理，不能按默认 nspin=1 静默执行。

本批次不提升成熟度，也不自动加入 Paimon v1.3 稳定面；实验性调用可按 discovery 和版本能力选择。进入稳定面仍需后续 compat、benchmark、clean-environment 与 real-smoke 证据，由上层决定是否消费。

风险与开放项

风险：不同 PyATB 版本可能对 property 或结果文件有额外限制。本设计只依据本地 PyATB `80f7c2d` 的通用 ABACUS HR route 规则，未把某个 property 的兼容性推断到 Forge。

开放项：无阻塞决策。真实 nspin=4 smoke 由后续验证计划补齐；若加入 PyATB property、spin texture 或更多输出布局等新能力，再另起 SPEC/PLAN，并由上层承担科学解释与编排。

收敛依据：上位 SPEC 已把 PyATB properties、nspin 4 和真实运行证据列为独立批次；本设计只解除当前 typed handoff 与 PyATB 已有输入规则之间的事实不一致。

本文件是 typed PyATB nspin=4 交接的批准 SPEC；实现与验证按关联 PLAN 执行。它不改变通用 result、manifest、事件或 legacy helper。
