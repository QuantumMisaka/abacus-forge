摘要

typed pyatb-band 已经能够在显式 workspace 中完成 prepare、execute 和 collect，但当前结果中的 ArtifactRecord 只有通用 role，prepare 的 pyatb_handoff 与 collect 的显式文件列表也没有统一的 PyATB 产物语义。Agent 因而可以拿到文件，却不能稳定知道某个文件是 HR、SR、band data、band plot 还是运行输入。

本设计新增 capability 专属的 pyatb_manifest/v1 诊断对象。它嵌入现有 forge.result/v1 envelope 的 diagnostics，不改变通用 result、ArtifactRecord、事件、旧 API 或 legacy CLI。manifest 只描述 Forge 已经实际处理或调用方明确声明的文件，返回路径、语义 kind、可确定的 spin、媒体类型、哈希和当前 envelope 内的 artifact id。

核心结论：先固化 PyATB 产物映射，再考虑 typed export 或真实 smoke；不把这个切片扩展成 SCF→PyATB workflow、属性计算或科学判定。

目标与非目标

目标

  • 为 typed pyatb-band 的输入 handoff 和显式输出提供一个稳定、可解析的 forge.pyatb-manifest/v1 语义层。
  • 让 Python API 与 Agent-first CLI 在隔离 workspace 中产生等价 manifest、artifact id、路径和收集事实。
  • 保留 workspace containment、link/copy provenance、缺失/越界/解析不完整事实，并使 manifest 与现有 artifact refs 一一对应。
  • 让未知文件保持可见但不被猜测；无法从请求或文件名确定 spin 时写 unknown。

非目标

  • 不修改通用 forge.result/v1、ArtifactRecord 字段或 forge.operation-outcome/v1。
  • 不扫描 sibling SCF workspace，不从日志推导矩阵、Fermi 或任务关系，不读取“最近一次”结果。
  • 不加入 nspin 4、PyATB properties、SCF→NSCF/PyATB 编排、typed export、重试/恢复、调度或平台语义。
  • 不生成科学接受、拒绝、收敛或质量结论；band_gap 仍只是 reported parser fact。
  • 不改变 prepare_pyatb_band、run_pyatb、collect_pyatb、run_band_sequence 等 legacy helper。

需求与验收

ID需求验收信号
M1成功的 typed prepare/collect diagnostics 必须包含 pyatb_manifest；其 schema_version 固定为 forge.pyatb-manifest/v1，并包含 inputs、outputs、missing 三个数组。失败 envelope 不伪造 manifest。typed API 与 machine CLI 对同一 fixture 的 manifest 可 JSON round-trip；旧 envelope 字段和 legacy 输出不变。
M2输入 entry 至少记录 path_rel、kind、spin、artifact_id、sha256（目标文件哈希）；来自显式 handoff 的 entry 还记录 source_path_rel、handoff_mode、source_sha256。prepare 的 STRU、HR、SR、rR、Input、KPT_band 均能映射，artifact id 能在同一 envelope 的 artifacts 中找到。
M3输出 entry 至少记录 path_rel、kind、spin、media_type、artifact_id、sha256 和 size_bytes。不存在、越界或不可访问的路径进入 missing 并带 reason；哈希读取失败属于不可访问，使用既有 collector 新增的 unavailable_output_paths_rel 事实；存在但 parser malformed 的真实文件仍可作为 output artifact，解析不完整继续由既有 diagnostics 表达，不伪造不存在的 artifact。collect 覆盖 band_info、band data、PNG/PDF、Out/input.json 及未知显式路径；partial/missing 状态与现有 diagnostics 保持一致，并区分 unavailable 与 parser malformed。
M4kind 只使用有限的 PyATB 语义集合：structure、matrix_hr、matrix_sr、matrix_rr、pyatb_input、kpoint_path、band_info、band_data、band_plot、run_input、other。spin 只可为 up、down、shared、total、unknown。映射表和未知/歧义文件测试钉死；不根据文件内容或科学常识猜测 spin。
M5artifact id 是当前 envelope 内的本地 id，不是跨 operation 的 ArtifactRef；manifest 不引入 operation/task/调度关系。prepare 与 collect 各自独立产生 manifest；execute 不读取或修改先前 manifest/event，也不把上游结果隐式拼入自身 envelope。
M6所有 manifest 路径遵守现有 workspace-relative containment；manifest 生成失败沿用现有 persistence/internal error 映射。路径越界、外部 symlink、文件消失、哈希读取失败和事件持久化失败均有回归，且不改变既有 exit class。
M7manifest 仅在 typed pyatb-band 面出现；legacy helper、旧 forge-unit.json 字段和旧 CLI 默认输出保持兼容。legacy PyATB suite 与完整离线 suite 通过，兼容 diff 只包含新增 typed diagnostics/tests/docs。

entry 的字段约束按数组语义执行：inputs/outputs 中代表已处理文件的 entry 必须带同 envelope 的 artifact_id、sha256、size_bytes；missing entry 必须带 reason 且不得带 artifact id。值对象可以保留稀疏构造能力以表示 missing，但 builder 不得产生违反上述语义的 wire entry；reason 只出现在 missing 数组。

设计决策与替代方案

D1：使用 capability 专属 diagnostics manifest。现有 ArtifactRecord 已能承载通用 role、media type、hash 和 size；直接给它增加 PyATB kind/spin/source 字段会扩大所有 capability 的 v1 契约。将语义放在 pyatb_manifest 可让 Agent 获得稳定信息，同时把变更限制在 PyATB。

D2：只索引显式输入和显式输出。prepare 使用已有 handoff 记录；collect 使用请求中的默认/可选路径。Forge 不目录扫描，未知但显式声明的文件以 other 保留，避免因命名差异丢失事实。

D3：spin 只做可证明映射。HR/SR/rR 的 spin 来自 prepare 的请求语义：HR 在 nspin=1 时为 shared、nspin=2 时按请求顺序分别为 up/down，SR/rR 为 shared；collect 的 band_up.dat/band_dn.dat 可按稳定 basename 映射，band.dat、图片和 band_info.dat 默认为 unknown，除非请求或已有明确 metadata 证明，否则不写 total。

D4：manifest 不建立跨 operation 引用。artifact_id 只指向同一 envelope 的 ArtifactRecord.id；跨 operation 的 ArtifactRef、来源 operation 和编排关系仍由上层处理。

替代方案：扩展通用 ArtifactRecord 被否决（影响面过大）；新增独立 manifest 文件被暂缓（会引入多文件一致性和新的持久化协议）；自动扫描标准输出被否决（会重新引入隐式目录语义）。

架构与数据流

manifest 是结果 envelope 的一个 capability-specific diagnostics projection，不是新的执行状态机：

typed request
  ├─ prepare helper ── explicit handoff records ──┐
  └─ collect helper ── declared output records ───┤
                                                    ▼
                          pyatb_manifest/v1 + generic ArtifactRecord
                                                    ▼
                         existing ServiceContext.persist → event
  • prepare：从 handoff role 和生成文件路径构造输入 entries；把 source/destination hashes、link/copy provenance 和当前 envelope artifact id 对齐。forge-unit.json.metadata.pyatb_handoff 保持已有字段，manifest 不替换它。
  • collect：只处理 request 明确的 band_info_path_rel、data/picture paths；现有 artifact records 先生成，再由相同 path 映射得到 manifest entry。已知 .dat band 文件使用 text/plain，PNG/PDF/JSON 使用对应固定 MIME，其他文件使用 application/octet-stream；哈希读取失败单独记录为 unavailable_output_paths_rel，parser malformed 文件仍保留为真实 output artifact；band gap parser 的结果仍走现有 MetricRecord(kind="reported")。
  • 服务/API/CLI：服务层调用同一 helper，machine CLI 只负责解码、路由和渲染；manifest 不改变 admission、event、status 或 artifact-ref 单点持久化。

错误处理

  • manifest 是对已有结果的投影；路径、请求、文件读取和持久化继续使用现有 request.invalid、request.path、precondition.missing、persistence.failure、internal.failure 映射。
  • 缺失、外部 resolved symlink、非普通文件和哈希读取失败不创建伪造 entry，进入 missing；其中哈希读取失败通过 unavailable_output_paths_rel 映射为 reason="unavailable"。存在但 parser malformed 的文件保留真实 output artifact，并保留现有 collection diagnostics/status。
  • manifest 不改变 execution、collection、scientific 或 process exit；尤其不把 band gap、文件齐全或 plot 存在转成接受结论。
  • artifact id 不存在、manifest 与 envelope 不一致或 manifest 序列化失败属于内部/持久化问题，由既有 service persistence gate 报告；不自动重试、不回收 admission。

测试与门禁

  • 契约：manifest schema/version、kind/spin 枚举、JSON round-trip、unknown-path fallback、artifact id 对齐。
  • prepare：spin-1/2 handoff、link/copy、hash/provenance、generated Input/KPT 和无部分写入。
  • collect：标准 band_info/data/plot/run-input、up/down basename、unknown 文件、missing/partial/escaped/unavailable/malformed，及 reported-only band gap。
  • parity：同一隔离 fixture 经 Python API 与 machine CLI 产生等价 diagnostics、artifacts、refs、状态和 exit class；CLI stdout 仍为单 JSON envelope。
  • 兼容/架构：legacy PyATB tests、完整离线 pytest、architecture/forbidden-import/discovery gates、git diff --check。真实 PyATB/ABACUS smoke 不在本切片声称。

实现前的 PLAN 必须将每个测试分为 RED→GREEN，并明确只改 typed PyATB 文件和必要文档；不得顺便引入 typed export、nspin 4 或属性 selector。

兼容与发布

manifest 只在 experimental pyatb-band typed service 的 diagnostics 中出现；旧 API、旧 CLI、旧文件消费者和通用 result schema 不需要迁移。已有消费者可忽略未知 diagnostics 字段；需要语义映射的 Agent 读取 schema_version 后再消费。

本切片不提升 capability maturity，不构成真实计算或科学结果证据。后续 typed export 必须另行设计并显式消费 artifact refs；real-smoke 必须在独立门禁中验证实际 PyATB/ABACUS 进程与产物。

风险与开放项

已知风险：不同 PyATB 版本可能使用额外文件名或输出布局；本设计通过显式路径和 other/unknown 保留事实，不宣称未知文件的领域语义。未来扩展映射必须带独立证据和版本化变更。

需要审阅的唯一决策：是否接受“capability 专属 diagnostics manifest、通用 ArtifactRecord 不变、未知文件不猜测”的公共边界。批准后再写实现 PLAN；若不批准，应在实现前明确替代的 schema 归属和兼容窗口。

依据：当前 typed PyATB plan、Forge 两份批准 SPEC、现有 ArtifactRecord/ServiceContext.persist 实现，以及 abacus-agent-tools、abacuslab 和本地 PyATB 的输入/输出审计。

本文件是审阅草案，不改变当前 Forge 代码或已批准 SPEC；批准后才进入 writing-plans 和实现。
